# dsh 0.2.2-rc.5: the same harness, three patch releases later

**Date:** 2026-11-23
**Status:** accepted
**Changes:** the CI matrix's 0.2.2 leg, the e2e contract header, and the
running plan record

dsh `0.2.2-rc.5` was published on 2026-11-18 and is now both npm's `latest`
and `next`. rc.2, which the matrix has measured since 2026-11-12, had held
`next` only while rc.3–rc.5 arrived. This document asks the same narrow
question as its rc.2 predecessor: **does the shop work against rc.5, and did
anything it depends on move?** Everything below was measured against two
installed harnesses, `0.2.2-rc.2` and `0.2.2-rc.5`, side by side.

---

## 1. What changed in the harness

rc.3–rc.5 are patch releases on the same 0.2.2 line. 326 of the 337
`@deepseek-ai/*` packages in the installed tree moved from rc.2 to rc.5; the
cordis family did not (`cordis` 4.1.0 and `cordis-plugin-include` 1.1.0,
identical to rc.1 and rc.2). The release notes name three changes:

| release | upstream change |
|---|---|
| rc.3 | an experimental DeepSeek chat-import plugin; a Windows desktop in-app update fix |
| rc.4 | handling of unexpected model responses; a LiveShare desktop share fix |
| rc.5 | DeepSeek models use server-side search; other models default to the DeepSeek Search API |

None is a harness service the shop reads.

## 2. What the shop reads, and whether it moved

Compared by importing both installs:

| package | rc.2 | rc.5 | |
|---|---|---|---|
| `dsh-app-boot` | 57 exports | 57 exports | same names |
| `dsh-official-bundles` | 12 exports | 12 exports | same names |
| `dsh-home-paths` | 16 exports | 16 exports | same names |
| `dsh-plugin-manager` | 6 exports | 6 exports | same names |

`PluginManager.prototype` carries the same 40 members in both, the six the
shop calls (`installBundle`, `removeBundle`, `updateBundle`,
`setBundleEnabled`, `setPluginEnabled`, `cancelInstall`) included.
`dsh-official-bundles` still exports `PROFILE_TEMPLATES` with the same five
keys — `acp, headless, sdk, sdk-minimal, web` — so the `harness-profile`
badge measured in the rc.1 audit still fires.

The shop's harness peers are `>=0.1.1-rc.2 <0.3.0-0`, which admits rc.5 under
dsh's own rule; `repo-guards.test.ts` holds that range and the matrix
together.

## 3. The e2e, run against rc.5

On 2026-11-23, on local Node 22.23.2 (dsh 0.2.2 declares `>=24.9`; it boots
and passes there, as rc.1 did — CI uses Node 24), with
`DSH_SHOP_EXPECT_DSH=0.2.2-rc.5` so that a `dsh` answering any other
`--version` fails the run instead of making it vacuous:

| | |
|---|---|
| package suite | **57 files / 2028 tests, 0 skipped, exit 0** |
| `web-full-flow.e2e.ts` (P2) | **12 / 12 pass** |
| `real-install.test.ts` (P1) | **3 / 3 pass** |

The first attempt failed with `spawn pnpm ENOENT` in both exit-criterion
files: that shell had no `pnpm`, and dsh's plugin manager spawns one. That is
a local environment gap, not a harness finding — with pnpm 11.7.0 on PATH the
same suite was green. The run is recorded at
`.scratch-dsh022r5/rc5-full-clean.log`.

Every version branch in the e2e is a `gte()` threshold (`0.1.7-rc.1`,
`0.1.7-rc.2`, `0.2.1-rc.1`), and none of them compares a patch number, so
rc.5 takes the same branch rc.2 took.

## 4. What this does not mean

- **It does not move what users install.** The shop version is unchanged.
- **It does not make rc.2–rc.4 measured legs.** The matrix lists a harness
  BEHAVIOUR, not every patch; rc.2 leaves the matrix as rc.5 takes its
  place, and rc.3/rc.4 are covered by this audit only.
- **It does not retire rc.2 from the world.** A user still on rc.2 runs the
  shop against it; the 2026-11-12 audit remains the record for that harness.

## 5. What changed in this repository

- `.github/workflows/plugin.yml`: the `dsh` matrix axis, `0.2.2-rc.2` →
  `0.2.2-rc.5`, and the comment that records which harness each leg is.
- `packages/dsh-plugin-shop/tests/client/web-full-flow.e2e.ts`: the contract
  header, which `repo-guards.test.ts` holds equal to that axis.
- `docs/plans/2026-08-18-remaining-work.md`: item 13, the running record of
  harness versions.
