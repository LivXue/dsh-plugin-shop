# P2 Client Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `packages/dsh-plugin-store/src/client/` — the browser half of dsh-plugin-store: one tab in `settings.plugins.tab` that browses the catalog, acknowledges and installs plugins, toggles enablement, and lists outdated installs — such that the XSS regression (spec §11.3.4) passes and the full flow works in a web profile (spec §12 P2 exit criterion).

**Architecture:** The client half follows the dsh `dsh.client` convention (package.json `dsh.client` block + `exports["./client"]`; the Node half bundles it into the boot graph). Its `apply()` mounts the store Remote itself — `ctx.remote.$mount(TYPERT_REMOTE)` with the package's own generated `./remote` face — then registers one lazy tab into the `settings.plugins.tab` slot, exactly as `@deepseek-ai/dsh-client-ui-settings-plugin-inventory` does. All policy/presentation logic lives in a pure module (`present.ts`) driven by fixtures; the React tab is a thin renderer; the polling hook is the only impure client piece. It touches neither the network nor the filesystem directly — every capability is one of the five `store/*` methods.

**Tech Stack:** React (seeded by the web shell), css-modules, `@deepseek-ai/dsh-client-ui-slots` + `@deepseek-ai/dsh-client-ui-primitives` (seeded), zod (bundled into the client bundle — the purity gate's `neverBundle('zod')` is false), vitest + jsdom + @testing-library/react, playwright (the e2e task).

**Spec:** [docs/design/2026-08-18-dsh-plugin-store-design.md](../design/2026-08-18-dsh-plugin-store-design.md) — the authority. The P1 host plan [2026-08-25-p1-host.md](2026-08-25-p1-host.md) defines the `store/*` shapes the client consumes. The dsh source checkout at `/tmp/dsh` is the API reference for anything the plan does not quote verbatim (`packages/client/ui-settings-plugin-inventory/` is the model package).

## Global Constraints

- **The Client holds no privilege** (§5.3): everything it can do is the five `store/*` methods. No network, no filesystem, no other Remote.
- **`summary` and `description` render as plain text** (§9.2): no Markdown, no links, never `dangerouslySetInnerHTML`. This text comes from a third party's `package.json` and reaches the browser. The XSS regression (spec §11.3.4) pins it: a summary of `<img src=x onerror=...>` renders as text.
- **A derived listing renders as unclaimed** (§6.1): `metadata === 'derived'` entries show an unclaimed marker; never presented as author-written.
- **`capabilities` is self-declared and unenforced** (§6.1, §14): the UI copy must not let it read as an enforced permission list.
- **The community-tier acknowledgement** must say what §9.3 says, verbatim in English: "Once installed, this plugin holds the same privileges as a built-in one: reading and writing your files, running shell commands, and reading and modifying the requests sent to the model. It has not been reviewed." The zh copy states the same facts in its own register. Wording like "please install with care" is not acceptable.
- **`verified-stale` shows "reviewed vX / current vY unreviewed"** (§7.1): the tier downgrade must be visible per version, never attached to the name alone.
- **Install flow** (§7.2): call `store/installStart({ name, version, acknowledged })` (the wire name per the §7.3 amendment; the injected client face keeps the name `install`); on `{ ok: true, installId }` poll `store/installStatus({ installId })` once per second (polling, never pushed); on `done` show "installed; restart dsh to activate" (§8 — no restart endpoint); on `failed` show the stderr log and the recovery hint from `detail` verbatim.
- **The four rejection results** (`not-in-catalog`, `denied`, `version-mismatch`, `needs-acknowledgement`) render their author-readable `detail` as text — the Host's strings are published copy; do not re-word them.
- **Catalog state** (§10): `stale: true` → label the snapshot with its `builtAt` date; a schemaVersion the client does not support → refuse to load and prompt to upgrade dsh-plugin-store; catalog unreachable with no cache → an error state with a retry.
- **Wire envelope**: every Remote call returns `{ ok: true, value } | { ok: false, error: { code, message } }` — the client unwraps, and on `!ok` shows the error state (never a bare crash).
- **Enable/disable is hot** (§8): after `store/setEnabled` the UI says the change applies without a restart.
- Bilingual user-facing copy (zh + en dictionaries, zh as the key source of truth — the inventory package's convention); ESM; `.ts`/`.tsx` relative imports with extensions; one trailing newline; `strict` + `noUncheckedIndexedAccess`.
- Client bundle purity: value imports only from the seeded baseline (react, react-dom, `@deepseek-ai/cordis`, `@deepseek-ai/dsh-client-ui-slots`, `@deepseek-ai/dsh-client-ui-primitives`), the parser-preloaded runtime, or bundled (zod, the package's own `./remote` face). Cross-plugin imports are type-only.

''` and the log; `rejected` → rejected; other events are no-ops returning the state.
  - `export const INSTALL_POLL_MS = 1000` — the §7.2 once-per-second cadence, as a named constant.

import { useCallback, useEffect, useRef, useState } from 'react'
import { INSTALL_POLL_MS, reduceInstall, type InstallView } from './present.ts'
import type { InstallArgs, StoreInstallResult, StoreInstallStatusResult } from '../host/index.ts'

export interface UseInstallResult {
  view: InstallView
  start: (args: InstallArgs) => Promise<void>
  reset: () => void
}

/** Drive one install: rejections, the polling loop at INSTALL_POLL_MS, and terminal states. */
export function useInstall(
  install: (args: InstallArgs) => Promise<StoreInstallResult>,
  installStatus: (args: { installId: string }) => Promise<StoreInstallStatusResult>,
): UseInstallResult {
  const [view, setView] = useState<InstallView>({ kind: 'idle' })
  const viewRef = useRef(view)
  viewRef.current = view

  const start = useCallback(async (args: InstallArgs) => {
    setView({ kind: 'idle' })
    const result = await install(args)
    if (!result.ok) {
      setView({ kind: 'rejected', code: result.code, detail: result.detail })
      return
    }
    setView({ kind: 'running', installId: result.installId, log: [] })
  }, [install])

  useEffect(() => {
    if (view.kind !== 'running') return
    const timer = setInterval(() => {
      void installStatus({ installId: view.installId }).then(status => {
        setView(current => reduceInstall(current, { type: 'status', status }))
      })
    }, INSTALL_POLL_MS)
    return () => clearInterval(timer)
  }, [view, installStatus])

  return { view, start, reset: useCallback(() => setView({ kind: 'idle' }), []) }
}
